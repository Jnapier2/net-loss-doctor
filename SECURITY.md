# Security and privacy

## System effects

NetLossDoctor is diagnostic-only: it writes report files inside the selected report directory and creates/removes its own temporary files and jobs. It does not change network or security configuration and does not request elevation.

The default invocation runs only a local self-test. Active probes require an explicit mode. Pktmon and `netsh trace` are independent, administrator-only opt-ins. Pktmon is skipped when an existing or unreadable filter set is detected; the diagnostic adds and removes only its uniquely named filters. Both capture lifecycles have function-level and outer `finally` cleanup.

The diagnostic never changes clipboard contents.

## Sensitive output

Raw reports may reveal host names, user names, IP and MAC addresses, DNS and gateway configuration, Wi-Fi SSIDs, nearby networks, driver inventory, routes, event messages, and visited endpoints visible to an optional capture. Store reports as operationally sensitive data.

- Do not commit `exports/` or generated archives.
- Prefer the compact redacted export over raw traces.
- Review the final files manually before sharing.
- Share ETL, PCAPNG, and raw modem pages only with a trusted recipient through an approved channel.
- Remove reports when the support purpose is complete.

The diagnostic does not collect account passwords, API keys, browser cookies, or application credentials by design. Packet captures can still contain sensitive metadata or payload fragments generated by other applications.

## Responsible reporting

Use the repository's private vulnerability-reporting channel when available. Do not attach a real diagnostic bundle to a public issue. A useful report includes the affected version, safe reproduction steps, and a synthetic or redacted example.

This project has not received an independent security audit.
